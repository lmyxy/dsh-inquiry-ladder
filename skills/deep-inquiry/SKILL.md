# 分层追问

当用户丢来一篇论文、一份报告、一节教材、一段代码说明，并且想要「深入思考 / 帮我问透它 / 它有什么问题 / 还有哪些没被论证」时，用这条流程。目标不是总结，而是**把材料变成一串有依赖关系的质疑，并逼出答案的边界**。

## 流程

1. **拿到文本**
   - PDF：先 `paper_brief`（paper-miner）拿到论证骨架，把返回的文本作为 `text` 传给 `inquiry_open`。不要自己复制整篇 PDF。
   - 网页：直接 `inquiry_open` 的 `url`；抓不到再让用户贴正文。
   - 对话里已给的内容：直接 `text`。

2. **建立追问**：`inquiry_open`，用 `focus` 写明你最想追的角度。它会返回 L0 定位和三个入口。

3. **逐层推进**：`inquiry_probe`。
   - 一次只推进一层，读完再决定下一层盯什么——**追问的价值在于中途改方向**，不在一次跑完。
   - 用户说「继续追问」→ 再来一次；想让某一层问得更狠 → `focus`；觉得走偏了 → 用 `operator` 强制换算子。
   - 需要一口气推完时说 `auto: true`（最多连推 3 层）。

4. **收口**：`inquiry_report`，把路径给用户，并把「一句话结论 + 仍在追的问题」贴出来。

5. **回看**：`inquiry_view` 不花模型调用，可以随时展开某一层。

## 算子语义（决定这一层问什么）

| 算子 | 什么时候用 |
|---|---|
| `orient` | 刚开始，确认它在跟谁竞争 |
| `decompose` | 论证结构不清，先切出断言 |
| `premise` | 结论听着对，但不知道它默认了什么 |
| `evidence` | 有实验/数据，怀疑基线与指标 |
| `boundary` | 想知道什么时候失效 |
| `rival` | 现象可能有别的解释 |
| `predict` | 想把结论变成一个可做的实验 |
| `transfer` | 想从这篇里长出自己选题 |

## 判好坏的三个硬指标

1. **锚点**：每个问题都引原文（「」里是原句，括号是 quote id）。没有锚点的问题不算数。
2. **来源**：每条答案带 `[E1]`–`[E4]`。E1 原文实测，E2 原文推理，E3 领域常识未核，E4 推测。看到 E3/E4 就要提醒用户「这条要自己核」。
3. **对抗**：每层必须有一个替代解释或反例。全都是「有道理」的报告是失败的。

## 成本

一层约 3 次模型调用、8–12k token；五层加报告约 60–80k token。开始前如果用户对成本敏感，先说清楚，并把 `depth` 调小（3 层足以看出材料成色）。

## 不要做的事

- 不要用这个流程做摘要或翻译——那是另一个任务。
- 不要在报告里堆原文，报告只留锚点和判断。
- 不要把 `inquiry_probe` 的输出原样复述给用户，挑「这一层改了什么判断」说。
