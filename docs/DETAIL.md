# 层层追问 Inquiry ladder

给一篇论文、一份报告、一节教材或任意长文做**分层追问**，再把材料里藏着的科研问题挖出来。它不总结材料：它把材料变成一串有依赖关系的质疑，逼出答案的边界，最后落到「所以我能做什么」。

## 它和「让模型自己问」有什么不同

三个角色由插件在 Host 内部分别调用，会话里只留每层约 400 token 的摘要：

- **提问者**：只问一个问题层级里的主问题，必须用「」逐字引用原文并标注 quote id，且必须由上一层答案里的某一处薄弱点触发；
- **应答者**：作答，每条结论用 `[E1 q3]` 标注证据强度与锚点（原文实测 / 原文推理 / 领域常识未核 / 推测），答不出的写进「答不出」；
- **审辨者**：找没有证据支撑的地方，并**至少给出一个替代解释或反例场景**——给不出，这一层就不许推进。

没锚点的问题会重生成一次；与旧问题重复的问法会被标出来；连续追问同一算子会被阶梯拦下。这些规则写在代码里，不靠模型自觉。

## 输入格式

`inquiry_open` 接受 `text`、`path`、`url` 三种来源。`path` 按扩展名自动抽取正文：

| 格式 | 处理方式 | 说明 |
|---|---|---|
| `.md` `.txt` `.rst` `.org` `.csv` `.tsv` `.json` `.yaml` `.toml` `.tex` `.bib` `.srt` | 直接读 UTF-8 | 剥掉 BOM |
| `.html` `.htm` `.xhtml` | 去标签、保留段落边界、解码实体 | |
| `.docx` | 内置 ZIP + OOXML 解析 | 保留标题层级、列表项与表格文本；纯图片文档会明确报错 |
| `.pptx` | 内置 ZIP + PresentationML 解析 | 按幻灯片序号输出 |
| `.epub` | 内置 ZIP + 章节 HTML | 按文件名自然序拼接 |
| `.pdf` | 外部提取器：`pdftotext`，否则 `python + pypdf` | 见下 |
| 其它文本扩展名 | 按纯文本读，并提示「未识别的扩展名」 | |
| `.doc` `.ppt` `.xls` `.pages` `.key` | 拒绝，提示另存为新格式 | 老二进制格式不做逆向 |
| 二进制（含 NUL） | 拒绝 | 不猜 |

PDF 不内置解析器：真正的 PDF 解析要处理字体、CMap、xref，做不完整比不做更糟。插件按顺序找 `pdftotext`（配置 `pdfTool` → PATH → TeX Live / poppler / MiKTeX 常见安装位），找不到再找装了 `pypdf` 的解释器（配置 `pythonPath` → `python`/`python3`/`py`）。两条都没有时会明确告诉你三条出路，而不是静默返回空文本。扫描件（抽出的非空白字符 < 200）也会被识别为「没有文字层」并报错。

## 八级阶梯（算子）

| 层 | 算子 | 问什么 |
|---|---|---|
| L0 | 定位 Orient | 它在跟谁竞争，作者承诺了什么 |
| L1 | 拆解 Decompose | 论证由哪几条断言撑起来，哪条是支柱 |
| L2 | 前提 Premise | 结论默认了什么没说出口的东西 |
| L3 | 证据 Evidence | 基线公平吗，指标测的是它声称的东西吗 |
| L4 | 边界 Boundary | 构造一个让它失效的场景 |
| L5 | 替代 Rival | 还有什么机制能产生同样现象，怎么区分 |
| L6 | 预测 Predict | 若为真，应观察到什么还没人观察到的现象 |
| L7 | 迁移 Transfer | 抽出的机制能搬到哪，换掉核心假设会怎样 |

默认只走到 L4（`maxDepth: 5`）。同一分支上相邻两层算子不重复，所以追问不会原地打转。

## 科研问题

`inquiry_problems` 回答的是「所以我能做什么」。一条问题必须同时满足五条：

1. 有锚点：指向 qN 或某一层暴露的弱点；
2. 不空泛：拒绝「更好的可解释性 / 更大规模的数据 / 更强的模型」这类命题（标题命中这些词且正文没有实质内容的会被直接丢弃）；
3. 落到可观测的量：什么场景、谁受影响、卡在哪一步；
4. 说清与作者的关系：作者已提及（缺什么）／未提及（为什么被忽略）；
5. 有最小实验：一个人一周内能开始，写清数据、对照、指标、预期。

问题分六类：**机制未解释**、**部署假设不成立**、**评测盲区**、**数据缺口**、**可迁移未做**、**前提脆弱**。产出按「可做性 × 影响」排序，第一条是最值得马上做的。

`inquiry_report` 在没有挖过问题时会自动补一轮，所以报告永远带着「研究问题清单」这一章，不会只批评不给出口。

## 工具

| 工具 | 作用 | 成本 |
|---|---|---|
| `inquiry_open` | 抽正文，生成证据骨架（主张、证据、隐含前提、作者自述局限与后续工作、逐字锚点），给出 L0 与三个入口 | 1–2 次调用 |
| `inquiry_probe` | 推进一层；`auto: true` 连续推进到收敛或预算用尽 | 3 次调用/层 |
| `inquiry_problems` | 从材料 + 已推进的层里挖 1–6 条科研问题 | 1 次调用 |
| `inquiry_view` | 看问题树或某一层全文 | 0 |
| `inquiry_report` | 生成 Markdown 报告（含科研问题章）；缺问题时自动补挖 | 1–2 次调用 |

所有调用转发取消信号，中途停止不会留下半条记录。追问记录在 `~/.dsh/inquiry/<id>/`，可断点续跑。

## 用法

```
inquiry_open(path: "论文.docx", focus: "它的评测协议是否公平")
inquiry_probe(inquiry_id: ..., focus: "只盯消融实验")
inquiry_problems(inquiry_id: ..., focus: "真实部署")
inquiry_report(inquiry_id: ...)
```

## 报告长什么样

1. 一句话结论；
2. L0 定位：核心主张、支撑断言、隐含前提；
3. 原文锚点表（quote id → 原句 → 位置）；
4. 问题树（缩进，标注每层算子与是否收敛）；
5. 分层追问记录：问、答、弱点、替代解释、反例、残留；
6. 弱点与未证前提汇总；
7. 仍开放的追问；
8. **现实科研问题**：每条含问题陈述、为什么是真问题、材料依据、与作者的关系、最小验证、风险与难度；
9. 合成判断：最有力的证据 / 最脆弱的环节、最值得继续追的问题、一个 1 天内能做完的验证动作。

## 配置（`cordis.patch.yml` 可覆盖）

| 键 | 默认 | 说明 |
|---|---|---|
| `maxDepth` | 5 | 1–7 |
| `maxCalls` | 20 | 单次追问的模型调用上限 |
| `maxTokens` | 150000 | 单次追问的 token 预算 |
| `autoMax` | 3 | `auto: true` 单次最多连推几层 |
| `roles.questioner` / `answerer` / `critic` | 继承会话模型 | 可分别给 `{provider, model}` |
| `pdfTool` | 空 | `pdftotext` 的绝对路径，覆盖自动探测 |
| `pythonPath` | 空 | 装了 `pypdf` 的解释器绝对路径 |
| `lang` | `zh` | 报告语言；`en` / `auto` |
| `strictAnchors` | `true` | 无锚点的问题重生成 |
| `maxSourceChars` | 48000 | 单次送入的源文本上限，超出会明确标注截断 |
| `reportDir` | `inquiry` | 报告目录（相对工作区） |

## 已知限制

- PDF 依赖外部提取器；没有 `pdftotext` / `pypdf` 时会报 `PDF_NO_BACKEND` 并给出三条替代路径。
- 扫描件与纯图片 PDF 没有文字层，会报「几乎没有可提取的文字」，需要先 OCR。
- 长文会截断到 `maxSourceChars`，报告里会写明截断事实；追问只能引用被保留的部分。
- 追问记录存在 `~/.dsh/inquiry/<id>/`，换机器或清缓存后无法续跑，需要重新 `inquiry_open`。
- `url` 依赖 profile 里的 web 服务；抓不到的页面请改用文件或 `text`。
- 报告质量取决于所选模型的结构化输出能力；某个角色的 JSON 连续两次解析失败会报 `BAD_JSON`，此时给该角色换一个模型（在 `roles` 里配）。输出被 `maxTokens` 截断时插件会自动以 4 倍预算重试一次。
