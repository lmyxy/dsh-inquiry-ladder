# 层层追问 Inquiry ladder

给一篇论文、一份报告、一节教材或任意长文做**分层追问**。它不总结材料，它把材料变成一串有依赖关系的质疑，并逼出答案的边界。

## 它和「让模型自己问」有什么不同

三个角色由插件在 Host 内部分别调用，会话里只留每层约 400 token 的摘要：

- **提问者**：只问一个问题层级里的主问题，必须用「」逐字引用原文并标注 quote id，且必须由上一层答案里的某一处薄弱点触发；
- **应答者**：作答，每条结论用 `[E1]`–`[E4]` 标注证据强度（原文实测 / 原文推理 / 领域常识未核 / 推测），答不出的写进「答不出」；
- **审辨者**：找没有证据支撑的地方，并**至少给出一个替代解释或反例场景**——给不出，这一层就不许推进。

没锚点的问题会重生成一次；与旧问题重复的问法会被改写；连续追问同一算子会被阶梯拦下。这些规则写在代码里，不靠模型自觉。

## 八级阶梯（算子）

| 层 | 算子 | 问什么 |
|---|---|---|
| L0 | 定位 Orient | 它在跟谁竞争，作者承诺了什么 |
| L1 | 拆解 Decompose | 论证由哪几条断言撑起来，哪条是支柱 |
| L2 | 前提 Premise | 结论默认了什么没说出口的东西 |
| L3 | 证据 Evidence | 基线公平吗，指标测的是它声称的东西吗 |
| L4 | 边界 Boundary | 构造一个让它失效的场景 |
| L5 | 替代 Rival | 还有什么机制能产生同样现象，怎么区分 |
| L6 | 预测 Predict | 若为真，应观察到什么还没人观察到的现象 |
| L7 | 迁移 Transfer | 抽出的机制能搬到哪，换掉核心假设会怎样 |

默认只走到 L4（`maxDepth: 5`）。同一分支上相邻两层算子不重复，所以追问不会原地打转。

## 工具

| 工具 | 作用 | 成本 |
|---|---|---|
| `inquiry_open` | 抽出可被追问的证据骨架（主张、证据、隐含前提、逐字锚点），给出 L0 与三个入口 | 1 次调用 |
| `inquiry_probe` | 推进一层；`auto: true` 连续推进到收敛或预算用尽 | 3 次调用/层 |
| `inquiry_view` | 看问题树或某一层全文 | 0 |
| `inquiry_report` | 生成 Markdown 报告到工作区 | 1 次调用 |

实测一层约 1.2–1.5 万 token（推理模型的思考也计入输出），五层加报告约 8 万 token、3–6 分钟。所有调用转发取消信号，中途停止不会留下半条记录。

## 用法

```
inquiry_open(text: <正文>)
inquiry_probe(inquiry_id: ..., focus: "它的评测协议是否公平")
inquiry_probe(inquiry_id: ..., operator: "evidence")
inquiry_report(inquiry_id: ...)
```

PDF 不要直接喂进来：先用 `paper_brief`（paper-miner）把论文压成论证骨架，再把文本作为 `text` 传入。这样既省 token，也保证追问引用的是原文句子而不是解析噪音。

## 报告长什么样

1. 一句话结论；
2. L0 定位：核心主张、支撑断言、隐含前提；
3. 原文锚点表（quote id → 原句 → 位置）；
4. 问题树（缩进，标注每层算子与是否收敛）；
5. 分层追问记录：问、答、弱点、替代解释、反例、残留；
6. 弱点与未证前提汇总；
7. 仍开放的追问、最值得继续追的问题、一个 1 天内能做完的验证动作。

## 配置（`cordis.patch.yml` 可覆盖）

| 键 | 默认 | 说明 |
|---|---|---|
| `maxDepth` | 5 | 1–7 |
| `maxCalls` | 20 | 单次追问的模型调用上限 |
| `maxTokens` | 150000 | 单次追问的 token 预算 |
| `autoMax` | 3 | `auto: true` 单次最多连推几层 |
| `roles.questioner` / `answerer` / `critic` | 继承会话模型 | 可分别给 `{provider, model}`，例如追问用强模型、应答用快模型 |
| `lang` | `zh` | 报告语言；`en` / `auto` |
| `strictAnchors` | `true` | 无锚点的问题重生成 |
| `maxSourceChars` | 48000 | 单次送入的源文本上限，超出会明确标注截断 |

## 已知限制

- 不解析 PDF，需要先走 `paper-miner`。
- 长文会被截断到 `maxSourceChars`，报告里会写明截断事实；追问只能引用被保留的那部分。
- 追问记录存在 `~/.dsh/inquiry/<id>/`，换机器或清缓存后无法续跑，需要重新 `inquiry_open`。
- `url` 依赖 profile 里的 web 服务；抓不到的页面请改用 `text`。
- 报告质量取决于所选模型的结构化输出能力；某个角色的 JSON 连续两次解析失败会报错（`BAD_JSON`），此时给该角色换一个模型。
- 推理型模型会先花掉一部分输出预算思考。插件在输出被 `maxTokens` 截断时会自动以 4 倍预算重试一次；仍被截断则报 `EMPTY_OUTPUT`。
